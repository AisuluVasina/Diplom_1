# Дипломная работа. Часть 2
## Задание 1. Юнит‑тесты для класса Burger (Stellar Burgers)

### Назначение тестов
Юнит‑тесты предназначены для проверки корректности работы класса `Burger`, который отвечает за сборку, модификацию и расчёт стоимости бургера в приложении Stellar Burgers. 

### Что тестируется
Тестируются ключевые методы класса `Burger`:
* `set_buns` — установка булочек и проверка корректности присваивания и цены;
* `add_ingredient` — добавление ингредиента в конец списка;
* `remove_ingredient` — удаление ингредиента по индексу и обработка ошибки при удалении из пустого списка;
* `move_ingredient` — перемещение ингредиента в списке и обработка выхода за границы индексов;
* `get_price` — расчёт итоговой стоимости бургера по формуле: `(цена булочки × 2) + сумма ингредиентов`;
* `get_receipt` — формирование текстового чека с валидацией формата и обработкой случая отсутствия булочки.

Для покрытия сценариев использованы:
* **параметризация** (`@pytest.mark.parametrize`) — для компактного тестирования множества комбинаций входных данных (цены, типы ингредиентов, наборы для расчёта стоимости);
* **моки** — в тесте `test_get_receipt_format_and_content` используются моковые объекты булочек и ингредиентов (`mock_bun`, `mock_sauce`, `mock_filling`) для проверки формата чека без привязки к реальным данным.

### Структура проекта
* `praktikum/` — пакет с реализацией приложения:
    * `burger.py` — класс `Burger` с методами сборки, модификации и расчёта стоимости;
    * `bun.py` — класс `Bun` (используется в тестах);
    * `ingredient.py` — класс `Ingredient` (используется в тестах).
* `tests/` — пакет с юнит‑тестами:
    * `test_burger.py` — тесты класса `Burger`, включая параметризованные тесты, тесты с моками и проверки граничных случаев;
    * `conftest.py` — фикстуры и настройки для моков (например, `mock_bun`, `mock_sauce`, `mock_filling`).
* `requirements.txt` — список зависимостей проекта (`pytest`, `pytest-cov`, `pytest-mock` и др.);
